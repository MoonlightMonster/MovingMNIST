# 整帧预测靠齐可行性验证结论

> 日期：2026-11-13 ｜ 触发问题：整帧预测是否比质心预测更贴合目标？能否靠齐？

## 一、核心结论

**可以靠齐，且是低成本的。现有编码器特征完全够用，只差一个"像素解码头"。**

关键证据（冻结 v5_anchor 编码器，只训练一个临时解码头）：

| 特征源 | 重建观测末帧 MSE（[0,1] 尺度） | 含义 |
|---|---|---|
| h1（16×16×128） | **0.0078** | 画面信息几乎完整保留 |
| h2（8×8×256） | **0.0230** | 即使 8×8 下采样仍保留大部分信息 |

结论：编码器特征**没有被分类/轨迹任务"榨干"**，画面信息仍在，之前只是缺解码头把它还原成像素。

## 二、验证过程中的关键认知

1. **最初的探测设计有缺陷**：我一开始用「观测末帧的单一 h2 特征」去解码「未来 10 帧」，这是错的——未来帧在运动，单一静态特征无法表示不同时刻的位置。这导致第一次 MSE 高达 148.7（误判为"特征不够"）。

2. **修正后的正确诊断**：改为「重建观测末帧本身」（同一时刻，运动无关），MSE 骤降到 0.0078/0.0230，证明特征信息量充足。

3. **真正的难点不是"有没有画面信息"，而是"如何预测未来的运动"**。整帧预测的未来帧需要「运动信息」，而这恰恰是轨迹解码器已经在做的（delta 位移）。所以正确做法是**复用轨迹解码器的运动预测**，而非静态解码。

## 三、可行方案（方向②：三任务头）

推荐「像素 + 轨迹 + 分类」联合多任务，而非「纯像素重建」：

```
输入 10 帧
  → 共享时空编码器（h1 16×16×128 / h2 8×8×256，已有）
      ├─ 分类头（已有，GAP）
      ├─ 轨迹解码器（已有，LSTMCell + delta）
      └─ 像素解码头（新增）：把"预测的位置"渲染回画面
```

**关键设计洞察**：不要用「静态 h2 解码未来帧」，而要**把轨迹解码器预测出的质心位置 + 身份外观，通过一个可微的"渲染器"画回 64×64 画布**。这样：
- 像素预测和轨迹预测**共享同一个运动来源**（轨迹解码器），不会打架；
- 像素监督（MSE）反过来约束轨迹预测更准；
- 天然输出"能看到未来 + 知道去哪 + 知道是什么"。

## 四、风险提示（吸取历史教训）

1. **多任务梯度冲突**（嵌入头教训）：像素损失权重需从小（如 0.1）起步，观察分类/轨迹是否退化。
2. **整帧预测易"糊"**：纯 MSE 会输出模糊帧，市面用 SSIM/LPIPS/GAN 缓解，但增加训练复杂度。**建议先用纯 MSE 跑通，不上 GAN。**
3. **未来帧的"运动"才是真难点**：静态解码（本验证）只能重建当前帧，预测未来帧必须依赖运动信息，这是下一步实现的核心。

## 五、下一步建议

若决定走方向②，实现顺序：
1. 在 `train_convlstm_v2.py` 加 `--pixel-head` 开关（默认关闭，向后兼容）；
2. 实现"轨迹位置 → 渲染未来帧"的可微渲染器（或先用简单 Conv 解码头 + h1_seq 逐步解码）；
3. 从 v5_anchor 微调，像素损失权重从 0.1 起，观察主任务是否退化；
4. 用 MSE/SSIM 评估未来帧质量，对比市面 ConvLSTM 基准。
