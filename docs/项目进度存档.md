### ✅ 步骤 1：CNN 分类基线（2026-08-23 完成）

- **结果**：test_acc **99.76%**，best val_acc 99.68%（epoch 17），20 轮约 4 分钟（GPU，每轮 ~13s）
- **文件**：`D:\MovingMNIST\train_classifier.py`
- **checkpoint**：`D:\MovingMNIST\checkpoints\mnist_cnn_best.pth`（含 epoch/model_state_dict/val_acc）
- **原理与实现要点**：
  - 模型 `MNISTNet`（585K 参数）：stem(1→32) + 3 个残差卷积块 ConvBlock(32→64 s2, 64→128 s2, 128→128)，每块 = Conv-BN-ReLU-Conv-BN + shortcut 残差连接；全局平均池化 AdaptiveAvgPool2d 取代大 FC；Dropout(0.25) + Linear(128→10)
  - 数据增强：RandomAffine(±10°, 平移10%, 缩放0.9~1.1)；Normalize 用 MNIST 全局均值 0.1307/方差 0.3081
  - 训练：AdamW(lr=1e-3, wd=5e-4) + CosineAnnealingLR + CrossEntropyLoss(label_smoothing=0.1)；55000 训练 / 5000 验证 / 10000 测试；按验证准确率保存最优 checkpoint；全局 seed=42 可复现
- **设计意图**：这套训练循环/评估/checkpoint 代码和卷积块结构要在步骤 3 直接复用（MNISTNet 的卷积块可拆作 ConvLSTM 的视觉编码器）

### ✅ 步骤 2：轨迹预测基线——线性匀速外推（2026-08-23 完成）

- **结果**（2000 条序列 × 2 数字，seed=2026，前 10 帧观测 → 后 10 帧预测）：
  - **ADE = 23.88 px**（64px 画布的 37.3%）
  - **FDE = 41.60 px**（65.0%）
- **文件**：`D:\MovingMNIST\eval_trajectory_baseline.py`
- **原理**：匀速外推 `v=(c_last-c_first)/(n_input-1)`，`c(t+k)=c_last+k·v`，无任何学习成分
- **关键洞察**：基线差是因为**撞墙反弹**——数字速度 3~5 px/帧而可活动范围仅 36 px（64-28），每 7~12 帧撞一次墙，10 帧预测窗内几乎必有 1~2 次反弹，线性方法无法处理。这给学习模型留了巨大空间，主模型 ADE 应能降到个位数像素
- **指标定义**：ADE=预测段所有帧平均欧氏距离(px)，FDE=最后一帧欧氏距离(px)
- 可视化样例：`D:\MovingMNIST\samples\traj_baseline.png`（白=观测/绿=真实未来/红=线性预测）

### 基础设施：Moving MNIST 在线合成器（已完成，步骤 3 的数据来源）

- **文件**：`D:\MovingMNIST\moving_mnist.py`
- **原理**：按论文 Srivastava et al. 2015《Unsupervised Learning of Video Representations using LSTMs》原始设定从静态 MNIST 合成：
  - 每条序列随机取 2 个数字放入 64×64 黑画布
  - 随机初始位置 + 随机方向速度（3~5 px/帧）
  - 逐帧推演，撞墙反弹（位置折回 + 该轴速度取反），数字重叠取像素最大值
  - 输出 20 帧
- **接口**：
  ```python
  from moving_mnist import MovingMNIST
  ds = MovingMNIST(root=r"D:\MovingMNIST\dataset\data", train=True,
                   n_digits=2, canvas_size=64, seq_len=20,
                   speed_range=(3,5), length=10000, seed=None)
  sample = ds[0]
  # video:   FloatTensor (20,1,64,64), [0,1]
  # labels:  LongTensor (2,)           数字类别
  # centers: FloatTensor (20,2,2)      每帧每数字质心 (x,y) 像素坐标, 原点左上
  ```
- **seed 机制**：`seed=None` 完全随机（训练用，无限数据）；`seed=整数` 时按 `RandomState(seed+idx)` 确定性生成（验证/测试可复现）
- 附带 `save_gif()` 可视化工具；示例在 `D:\MovingMNIST\samples\`（check.png 20 帧拼图已人工验证正确：移动/重叠/反弹均正常）

### 🔶 步骤 3 首版：ConvLSTM 多任务模型（2026-08-23 完成首训，未达标）

- **文件**：`D:\MovingMNIST\train_convlstm.py`（argparse 参数化；`--smoke` 快速自检）
- **checkpoint**：`D:\MovingMNIST\checkpoints\convlstm_multitask_best.pth`；指标存 `convlstm_multitask_metrics.json`
- **架构**（7.80M 参数）：每帧 CNN 下采样 64→32→16 → ConvLSTM(96ch@16²) → 下采样 → ConvLSTM(128ch@8²)，取最终隐状态；分类头=GAP+MLP→(2,10)；轨迹头=LSTMCell 解码器自回归推 10 步，第 0 步先锚定当前帧位置（辅助监督），训练推理一致 free-running
- **关键设计**：①槽位规范化——两数字按首帧质心 x 排序，槽位 0=更靠左，输出顺序有确定含义；②坐标 /64 归一化回归，指标换算回像素；③损失 = CE + 1.0·MSE(轨迹) + 0.5·MSE(锚定)；④AdamW + 余弦退火 + 梯度裁剪 1.0 + AMP
- **首训结果**（30 epoch，12800 序列/epoch 在线生成，~9 分钟；测试集 seed=2026 × 2000 条与基线同）：
  - **ADE 7.81 px**（基线 23.88，降 67%）✅ 大幅超越，但未达理想 <5
  - **FDE 9.98 px**（基线 41.60，降 76%）✅
  - **分类 95.6%**（逐数字）❌ 未达 99%
- **诊断**：30 轮时 val_ade / 分类损失仍在稳定下降，**未收敛**；可视化显示预测方向正确但有"向均值收缩"现象（MSE 典型行为），长轨迹会糊到中间

### 步骤 3 消融实验（2026-08-23，v2 脚本，均 30 epoch 同配置对照）

- **文件**：`D:\MovingMNIST\train_convlstm_v2.py`（消融开关版：`--cls-mode gap/slot`、`--traj-mode abs/delta`、`--traj-loss mse/huber`、`--detach-anchor`、`--h1-ch/--h2-ch/--dec-hidden` 容量参数、`--tag` 输出标识）
- **两处候选改进**：①轨迹改预测位移量累加 + Smooth L1(beta=0.02)；②分类头改按锚定位置 grid_sample 槽位局部特征
- **打包同训（v2，未消融）结果为负**：ADE 13.06 / 分类 93.9% —— 锚定损失卡死，根因是分类梯度经 grid_sample 污染锚定位置
- **逐个消融结论**：

| 配置 | ADE | FDE | 分类 |
|---|---|---|---|
| v1 对照 (gap+abs+mse) | 7.81 | 9.98 | 95.6% |
| v2 打包 | 13.06 | 13.43 | 93.9% |
| **v2a 只改轨迹 (delta+huber)** | **6.05** | **8.35** | 95.5% |
| v2b 只改分类 (slot+detach) | 7.82 | 9.91 | 82.0% |

- **关键教训**：
  1. 轨迹改动（位移+Huber）✅ 确认有效，采纳为新基线；v2a 第 30 轮仍在降
  2. 多任务共享中间量（锚定位置）时，**一个头的梯度会污染另一个头** —— v2b detach 后轨迹立即恢复（7.82≈v1），证实根因
  3. 槽位取样分类头即使 detach 也只有 82%，**"全局池化是分类瓶颈"的假设被证伪**；剩余 ~4.5% 错误需靠容量/训练量
  4. 一次只改一个变量 —— 打包改动导致 initially 误判方向
- **v3 结果**（v2a + 大容量 22.3M + 45 epoch，~23 分钟）：**ADE 6.02 / FDE 8.30 / 分类 96.8%**（best epoch 42）
  - 容量杠杆对**分类有效**（95.5%→96.8%），对**轨迹无效**（6.05→6.02，已到地板）
  - checkpoint：`checkpoints\convlstm_v3_best.pth`，指标 `convlstm_v3_metrics.json`，图 `samples\traj_convlstm_v3.png`
- **最终模型 = v4ft**（2026-08-24）：v4 + λ_cls=3 微调 15 轮（`--init-from v4 --cls-weight 3 --select acc --lr 3e-4`，~8 分钟）
  - **ADE 5.25 / FDE 7.28 / 分类 96.5%** —— 两指标均略优于 v4（Pareto 改进），分类 val 上曾达 97.2%
  - checkpoint：`checkpoints\convlstm_v4ft_best.pth`
  - **分类 96.5% vs 目标 99% 判定为本架构天花板**：取样式分类头两次独立证伪（v2b/v5），损失重平衡只带来 +0.3pt。差距集中在深度重叠样本，如需突破需换范式（如重建解耦、Transformer 关联），不在当前路线内
- **v4**（2026-08-23）：v3 + 轨迹解码器喂槽位级外观特征（`--slot-feat`，22.50M，45 epoch）—— ADE 5.27 / FDE 7.40 / 分类 96.2%；槽位交换率 30.2%→25.1%，非交换序列 ADE 4.15
- **v5 证伪**（2026-08-24，"--cls-mode clean"）："最干净帧"分类头（速度估计反推过去每帧位置 + 按帧间距离时间融合取样特征）——分类 82.6%、ADE 6.71，全面劣于 v4。与 v2b（82.0%）合看，**取样式分类头被两次独立证伪**：16×16 特征图单点取样的感受野远小于 28px 数字，局部特征不含身份信息；GAP 头才是最优分类方案。速度辅助损失还拖累了锚定质量（轨迹 5.27→6.71）——多任务共享中间量脆弱性的又一例证。此方向封存，不再尝试

## 四、原步骤 3 规划（已完成，存档备查）

**任务设定**：输入前 10 帧视频 → 同时输出 ①每个数字的类别 ②后 10 帧每个数字的质心轨迹

**架构规划**（共享时空编码器 + 双任务头）：

```
前10帧 (10,1,64,64) → ConvLSTM 编码器（CNN 提空间特征 + LSTM 建模时间）
                    → 最终隐状态/特征
                    ├─ 分类头：MLP/Conv → 每数字 10 类
                    └─ 轨迹头：LSTM/MLP decoder 自回归预测 10 帧 × 每数字 (x,y)
```

- **损失**：`L = λ1·交叉熵(分类) + λ2·MSE(轨迹)`，λ 待定（可从 1:1 开始调）
- **复用**：train_classifier.py 的训练循环骨架、moving_mnist.py 的数据
- **训练数据**：seed=None 在线生成（每个 epoch 数据都不同）；验证集固定 seed 如 2026
- **达标线**（来自基线）：
  1. 分类准确率 ≥ 99%（视频有重叠遮挡，比静态略难）
  2. 轨迹 **ADE 显著低于 23.88 px**（理想 < 5 px），FDE 低于 41.60 px
- **后续可选**：撞墙反弹点附近误差分析、预测轨迹叠加视频输出 gif、升级为 PredRNN/SimVP、增加数字个数提难度
